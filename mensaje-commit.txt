## What this commit adds

### New formal specifications (whitepaper §12)
- **§12.2** — Credential scope mechanisms: two-layer system (issuer scope declaration via
  path-pattern + per-credential [only-valid-for] restriction), verification flow with
  SCOPE-VERIFIED / SCOPE-UNVERIFIED / SCOPE-INVALID states, scope delegation via
  Authority/Agent pattern (§7.13)
- **§12.3** — ZKP direction: three concrete use cases (membership proof, attribute range
  proof, private/ existence concealment), candidate primitives (zk-SNARKs, zk-STARKs,
  Bulletproofs), integration point with hash_publico commitments
- **§12.9** — Distributed vocabulary repositories: formal structure, MUST rules, versioning
  via since/ timestamps, sector repositories under own domains
- **§12.9** — Alias declaration mechanism: formal structure with fields {}, MUST rules
  (one-way assertion, non-transitive, optional context path-pattern), divergence detection
- **§12.10** — Name discovery: three-component formal spec (self-declaration, third-party
  attestation via registry/names/, quorum-based conflict resolution), offline-capable
  verification sequence, explicit scope boundary (no name ownership)
- **§12.11** — Active authentication with key rotation: atomic 6-step rotation flow,
  security properties (forward secrecy, replay prevention, atomicity guarantee), path
  structure for auth/ audit log, MUST rules, comparison table vs emergency key
- **§12.14** — Social identity recovery via Shamir's Secret Sharing: guardian declaration
  under recovery/ with fields {}, recovery flow with consent publication, security
  properties (threshold resistance, guardian diversity, auditability), MUST rules,
  relationship to F.1
