## Style Guide changes

### §30 — path-pattern vs select-subset-from: The Decision Guide
- Decision flowchart: structural domain vs fixed enumeration
- When to use path-pattern: valid domain follows folder hierarchy,
  grows automatically with structure
- When to use select-subset-from: finite list known at schema design time,
  explicit additions required for new values
- Common mistakes with both patterns
- Summary rule: "whatever exists under this subtree" vs "exactly these options"

### §31 — Domain Migration Patterns: old-identities/
- Three migration scenarios:
  1. Personal domain change (both domains countersign — highest assurance)
  2. Institutional migration (new parent manages the chain, additive)
  3. Emergency migration (root gone, hash_publico proof, v9 assurance)
- Rules: receiving node maintains chain, full history published, permanent entries
- Verification sequence for credentials issued under old identities
- [migration-type emergency] declaration for absent countersignatures

### §32 — HTTP Integration Pattern: /.well-known/trusteando-proof
- Optional discovery endpoint (not a core protocol requirement)
- JSON response schema: trusteando_root, entity_id, hash_publico, trust_level,
  signed_by, proof_format, since, cache_ttl
- Client usage sequence: discovery → verification (separate steps)
- Trust Badge integration: entry point for browser extensions (§16.5)
- Visual vocabulary: t9/v9/b9/absent — absence of signal is not negative signal
- Server SHOULD and MUST NOT rules
- Relationship to protocol: well-known is discovery, graph is authority
